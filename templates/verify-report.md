# Verify Report：验收报告（R 审查阶段产出）

> Issue: #<编号> | 阶段: [R] Review | 状态标签: `riper-review`
> 产出角色: QA（见 `roles/reviewer.md`）——**T0：禁改业务代码；可写区域仅 `test/` 与本报告**
> 输入: `plan.md`（冻结基线及其修订记录）

**审查原则**：只认 `plan.md` 中的验收标准，逐条判定 PASS / FAIL / 无法验证；不接受"代码能跑就算过"。
**验证方式**：偏向**黑盒**（CLI / API / 端到端 / 文件产物）；如需测试脚本，**默认生成到 `test/`**（除非用户显性指定其他路径）。

## 5. 结论

- [ ] **全部 PASS 且无确认越界** → `riper-verified` → 按 references/integration.md 推送并核验 PR → 写回 URL/base/head/SHA 证据 → QA 关闭并释放认领；未交付保持 open
- [ ] **存在 FAIL** → 状态退回 `riper-plan`，PM 修订或确认原冻结计划仍有效后重新走 [E] → [R]
- [ ] **无法验证且无已确认 FAIL** → 不增加 retry、不 verified、不关闭；报告缺口与恢复条件，无法推进按权限 blocked 并释放认领
- [ ] **重试已达 3 次仍有 FAIL** → 状态 `riper-blocked`，等待人工介入
